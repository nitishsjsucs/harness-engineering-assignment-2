Three harnesses.
Built, broken, and shown working.

A model is a function from a list of messages to one message. Everything that makes it feel like a colleague lives in the loop around it. This is that loop — written by hand, extended inside a production harness, and pointed at research.

Repository The three parts Videos Run it

The idea

Models are interchangeable; the harness is the product. The same model behaves like a toy or like a colleague depending on what surrounds it: which tools it can reach, what it remembers, what it is allowed to run, what happens when the context fills up, and who says stop. Part A builds that loop by hand. Part B takes a production one apart. Part C points one at research instead of code.

The three parts

Part A

A harness from scratch

Fifteen runnable steps on the OpenRouter API. Each step is the previous one plus exactly one idea, so a diff between them shows that idea and nothing else.

  • One raw HTTP POST → tools → the agent loop
  • Skills, todos, sessions, rewind
  • Permissions, then a kernel sandbox
  • Compaction and subagents
  • Model fallbacks, a cost ledger, an installable CLI
Code Video
Part B

DeepSeek Harness, extended

A harness where everything is a plugin — including the agent loop. Customised in Creator mode, which lets the agent inspect the running UI and mount plugins into the live process.

  • 7 community plugins, one per extension point
  • Second Brain: memory the agent searches, in an Obsidian vault
  • Dino Break: a game from one sentence
  • 2 domain agents as presets, not forks
Code Prompts Video
Part C

An ML autoresearch harness

Edit one file, run under a fixed time budget, keep the change if the metric improved, revert if it did not — plus the guards that decide whether the loop produces knowledge or noise.

  • Driven by a model, unattended: −99.4% in 3m16s
  • One experiment rejected in 0.00 s: the diff reached the val split
  • Frozen evaluation files, hashed every run
  • A Claude Code plugin, or headless with no assistant

Run it

# clone
git clone https://github.com/nitishsjsucs/harness-engineering-assignment-2
cd harness-engineering-assignment-2

# Part A — offline tests need no API key
python3.12 -m venv .venv && .venv/bin/pip install -r part-a-harness-from-scratch/requirements.txt
.venv/bin/python part-a-harness-from-scratch/run_tests.py

# Part B — the DeepSeek Harness and every plugin
npm install -g @deepseek-ai/dsh
cd part-b-deepseek-harness
./scripts/install-community-plugins.sh web
./scripts/install-local-plugins.sh web
./scripts/install-presets.sh

# Part C — the autoresearch engine and its tests
.venv/bin/pip install -e part-c-autoresearch-harness
